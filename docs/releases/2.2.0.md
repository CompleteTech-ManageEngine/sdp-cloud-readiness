# Explicit per-instance credentials — 2.2.0

Implements issues #1–#4: one same-host assessment can assign separate collection keys to each instance. The shared transport selects credentials for inventory, details, child resources and field metadata. Authentication failure stops all assignments using the failed key and allows independent credentials to continue. Global request/time budgets and endpoint restrictions remain shared.

`--multi-key` offers secure per-instance prompts after scope discovery/recovery. `--credential-file` enables unattended environment-reference assignments bound to the source host/application context. Explicit reuse is supported; automatic cross-instance fallback is not. Profiles, command-line arguments and reports do not contain keys.

An optional global credential/context assignment collects the reviewed Orguser resource once when multiple instances are observed. Directory-only keys retain their endpoint restriction. Global access is not inferred from instance SDAdmin access or successful discovery. Missing authorization produces explicit unknown coverage.

Reports include sanitized credential-scope statuses and per-instance CSV credential status. See [setup](../guides/multiple-credentials.md) and [source review](../reference/multi-key-authorization.md). Existing single-key operation and separate-host assessment boundaries are preserved.

Portal-recovery input reaching EOF now preserves the original unavailable-discovery diagnostic instead of reporting a user interruption. Intentional Ctrl+C remains an interruption.

Validation evidence is recorded in [2.2.0 validation](../development/multi-key-validation.md). No live customer API or permission validation is claimed.
